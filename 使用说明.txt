ACB — Agent Context Bridge 使用说明（本机 Agent 交接）
====================================================

它解决的一件事：
  一个 Agent 干到一半没额度了，下一个 Agent 接手时不用再读长记录、不用再扫全仓。
  ACB 把当前项目的真实进度（代码 + 未提交改动 + 检查结论 + 推断出来的任务与下一步）封存下来，
  并渲染成一份交接简报；下一个 Agent 只读这一份文件（约 3 KB）就能接着干。

  另一件同样重要的事：交接不需要你当传声筒。注册项目时 ACB 就在项目里写下了两样东西 ——
    <项目>\AGENTS.md       一段 ACB 自己维护的接入块（不认识这个约定的客户端才需要你转述）
    <项目>\.acb\LATEST.md  每次封存都会重写的指针：当前是哪条交接、简报在哪、怎么自己封存
  主流 Agent 客户端打开一个项目都会先读 AGENTS.md，所以：接手的会自己去读指针，
  干到一半的那个会自己封存。你按的那一下只是"现在就封"，不是"把话带到"。

一、启动
  双击 release\ACB-win64\ACB.exe（或桌面上的「ACB 启动」快捷方式）。
  全程在本机运行，不联网、不上传任何代码。
  数据都在本机：项目注册表 ~/.acb/projects.json；交接包 <项目>\.acb\store\handoffs\<id>\。

二、交出去（当前这个 Agent 要停了）
  1. 顶部选中项目。第一次使用：把项目文件夹直接拖进窗口，或点「换项目 / 管理」→ 选择文件夹。
  2. 什么都不用写。「① 交出去」里那块浅色卡片就是 ACB 从现场推断出来的交接内容：
       任务   ← 最近一次提交标题（没有就用分支名）
       做到哪 ← diff 里真实新增的常量/函数/类名，按文件列出（+行/-行）
       下一步 ← 代码里留下的 TODO/FIXME 原文（含文件名与行号）+ 改了源码却没改的测试
     每一行都写着它的依据；觉得不对就展开「我来改 / 补充（可选）」覆盖它。
  3. （可选）想让**当前这个 Agent**多交代一点背景：点「（可选）催现在干活的 Agent 自己写份交接说明」，
     把它粘给正在干活的 Agent。它会把目标/已完成/下一步/别碰 写进 <项目>\.acb\NEXT.md，
     ACB 下次封存会自动采纳并标为"上一个 Agent 留下的话"（不冒充你的声明）。
     不催也行：接入块里已经写了该由它自己封存这件事。
  4. 若出现「审阅结论」的警告/阻塞，按每条后面的「出路」处理；警告需勾一次「我已确认」。
  5. 点「就这样，生成交接」。绿框会写明这次在项目里写了什么（接入块是新增/追加/已有不动，
     指针是否已重写）；交接简报就是 .acb\store\handoffs\<id>\HANDOFF.md。
  6. 换 Agent 时不用再做什么：它在同一个目录里打开项目，先读到 .acb\LATEST.md，
     再顺着指针读那份简报。只有不认识 AGENTS.md 约定的客户端才需要转述 ——
     那种情况展开「备用：还是想自己粘一段话给下一个 Agent」，点「复制这段话」。

  到这里主流程就结束了 —— 同一个项目、同一个目录，代码就在原地，不需要"还原"。

三、接过来 / 回到某次交接（想把某次封存的状态取出来看时才用）
  在「② 接过来」里：
    挑一条交接（默认最新一条）→ 填一个**新目录** → 点「先预览（不写盘）」
    → 看清将写入多少文件、撞了哪些 → 点「确认预览 → 还原到该目录」。
  还原后给出判定（可继续 / 需要配置环境 / 需要重新验证 / 恢复被阻塞）、逐项对账
  （一致 / 变更 / 只在包里 / 只在目标），并在那个目录写下 ACB-HANDOFF.md 与 ACB-RESUME-REPORT.md，
  同时装好接入块与 .acb\LATEST.md 指针 —— 在那个目录里打开的 Agent 同样不需要有人领。
  这个工具**不提供"就地覆盖当前工作区"**：那会毁掉没封存过的改动。要看旧状态就还原到别的目录。

四、让 Agent 直接调接口（比丢文件更省 token 的那条路）
  判据：接口如果不比"把 HANDOFF.md 直接丢给 Agent"省 token，它就不该存在。所以这条路的成本
  是量出来的，随时可复算：在项目目录跑 npm run tokens。本机实测（同一把尺子估算）：

    直接丢 HANDOFF.md 全文            1193 tokens   基准
    调接口拿摘要（level=summary）        276 tokens     23%
    只要文件清单（level=files）           27 tokens      2%
    MCP 只登记接手那一条 = 工具表 + 一次调用  509 tokens     43%
    60 个改动文件的大现场：摘要占简报的      19%   （摘要这一侧有上界，简报没有）

  三种调法，任选一种（都不需要人在中间传话）：
  1) HTTP —— 服务地址写在 ~/.acb/endpoint.json（桌面版随机端口也写在这里）：
       curl "http://127.0.0.1:<端口>/api/handoff-brief?at=D:\\dev\\my-project"
       加 &level=files 只要文件清单；加 &level=brief&format=text 才回简报全文。
  2) 命令行 —— 能跑命令的 Agent 最省（没有 MCP 的工具表开销）：
       node "release\\ACB-win64\\resources\\app\\cli.cjs" takeover <项目目录>
       末尾那行就是两边实测 token 对比。
  3) MCP —— 配置里务必只登记接手要用的那一条，别把 16 条全挂上（全挂 = 3319 tokens 的
     一次性工具表，比丢文件还贵）：
       command: node  args: ["<ACB 目录>/agent/mcp-server.mjs"]
       env: { "ACB_MCP_TOOLS": "handoff_takeover" }        # 要让它自己收尾就加 ",handoff_create"
     调用 acb.handoff_takeover，input 用 {"at":"<项目目录>"} 就行。
  返回里的 next 是推断、checks 是源端历史证据，都不等于本机已验证；要动手前照旧在本机复跑检查。

五、带凭据的项目怎么办
  .env 之类默认不进包（也不该进包）。ACB 会把它列进简报的「需要本机补齐」，
  需要运行它的机器自己放一份同名文件即可 —— 不要为了让别人能跑而把密钥拷进交接。

六、常见问题
  · 打包按钮点不动：按钮上写的就是原因（正在扫描 / 有阻塞 / 先确认警告）。
  · 项目里怎么多了个 AGENTS.md？那是 ACB 的接入块（八行），Agent 靠它自己去读交接、自己封存。
    不想让 ACB 写它：删掉 <!-- ACB:BEGIN --> 与 <!-- ACB:END --> 之间那段，
    再在项目根建一个空文件 .acb\NO-BRIDGE —— ACB 之后一个字节都不碰这个文件，
    但 .acb\LATEST.md 指针照写（封存与还原都还需要它）。
  · 交接清单里 AGENTS.md 显示为"改动"：只有接入块那几行时，ACB 会在审阅清单里单列一条提示，
    说明这是工具写的、不是你的改动；混了你自己的内容时就不再这么算（判据是逐行比对，不是文件名）。
  · 让 Agent 自己封存（不用人在界面点）：在那个目录里跑 LATEST.md 写的那条命令，
    或调用 ACB 的 Agent 工具 acb.handoff_create（input {"projectId":"prj_…","confirm":true}，
    taskName 留空就用推断结果）。
  · 推断出来的任务名不对：展开「我来改 / 补充」直接写一句，你写的永远优先于推断。
    推断只用了这些证据：分支名、最近 3 条提交标题、git diff 的新增行、未跟踪文件的头部、
    代码里的 TODO 标记、基线里的测试文件名 —— 它不猜、不编，没证据就照实说没有。
  · 想让每次打包自动跑测试：「换项目 / 管理」→ 检查命令，填如 npm test。
    失败也照样封存，失败本身就是交接内容，简报里会写清哪条没过、退出码多少、怎么复跑。
  · 记录里那一行「检查通过 / 未执行」是源端历史证据，接手方在本机复跑前不算已验证。
  · 换目录 / 换项目路径了：在「换项目 / 管理」里按新路径重新注册即可，封存的交接数据不受影响。
  · 窗口空白：删掉 ~/.acb 目录后重开（注册表清空，项目目录里的交接包不受影响）。
  · 大仓库第一次打包慢：基线历史要用 git bundle 打全量，进度条会显示卡在哪一步。
